# Example: Retail Sales (datetime features + time-series diagnostics)

Predicts daily `units_sold` from date, region, category, price and promo flag.

- **Data**: `data/retail_sales.csv` — fully synthetic, generated by `generate_data.py` with a fixed random seed (trend + weekly seasonality + promo effect + noise, 730 daily rows). No download dependency, always reproducible.
- **Run it**: `python examples/retail_sales_datetime/generate_data.py && python examples/retail_sales_datetime/run_example.py`
- **What the pipeline does automatically here**: expands `order_date` into year/month/day/day-of-week/is-weekend plus cyclical sin/cos encodings, one-hot encodes `region`/`category`, compares 5 regression models — **and**, because a datetime column plus a numeric target were both detected, automatically runs a *separate* time-series diagnostic pass: trend-strength regression, an Augmented Dickey-Fuller stationarity test, ACF/PACF plots, and a 12-day Exponential Smoothing forecast.

## Results (best of 5 compared models)

| Model | MAE | RMSE | R² |
|---|---|---|---|
| **Ridge, CV-tuned (best)** | **5.20** | **6.72** | **0.884** |

## Time series diagnostics

- Trend-only R²: **0.34** (a linear trend alone explains a third of the variance; the rest is weekly seasonality + promo effects, which the tabular model captures via the engineered date-part features)
- Augmented Dickey-Fuller p-value: **0.68** → cannot reject a unit root, i.e. the raw series is non-stationary (expected, since it has both trend and seasonality by construction)
